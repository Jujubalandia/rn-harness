# Architecture

**Analysis Date:** 2026-08-11

## System Overview

rn-harness is a **three-layer scaffolding framework** that installs templates, skills, and scripts into Claude Code, then orchestrates React Native project initialization with stack detection and selective rule application.

```text
┌─────────────────────────────────────────────────────────────────┐
│                    Claude Code Layer                             │
│         /new-rn-project  &  /rn-doctor Skills                   │
│    `skills/new-rn-project/SKILL.md`                             │
│    `skills/rn-doctor/SKILL.md`                                  │
└──────────┬───────────────────────────────────────────────────────┘
           │ Invokes
           ▼
┌─────────────────────────────────────────────────────────────────┐
│                 Installation & Template Layer                    │
│  install.sh (bash) / install.ps1 (PowerShell)                   │
│  `install.sh --profile [minimal|standard|strict]`               │
│                                                                  │
│  Copies to:                                                      │
│  - ~/.claude/templates/rn-20days/          ← project templates  │
│  - ~/.claude/skills/new-rn-project/        ← wizard skill       │
│  - ~/.claude/skills/rn-doctor/             ← health check skill │
│  - ~/.rn-harness/scripts/doctor.{sh,ps1}   ← CLI doctor        │
│  - ~/.rn-harness/hooks/profiles/*/         ← git hooks         │
│  - ~/.rn-harness/.profile                  ← active profile    │
└──────────┬───────────────────────────────────────────────────────┘
           │ Reads
           ▼
┌─────────────────────────────────────────────────────────────────┐
│          Project Layer (Generated by /new-rn-project)            │
│                                                                  │
│  CLAUDE.md                     ← filled with stack info         │
│  DECISIONS.md, TODO.md          ← project templates             │
│  docs/{01-06}*.md              ← 20-day phase templates         │
│  .githooks/{pre-commit,pre-push}  ← quality gates               │
│  .claude/rules/*.md            ← selective (stack-based)        │
│  .claude/settings.json         ← destructive op blocklist       │
│  .claude/hooks/pre-tool-use.sh ← runtime pattern blocking      │
│                                                                  │
│  (project structure created by create-expo-app)                │
└─────────────────────────────────────────────────────────────────┘
```

## Component Responsibilities

| Component | Responsibility | File |
|-----------|----------------|------|
| **Installer** | Clones rn-harness, copies templates/skills to `~/.claude`, sets profile | `install.sh`, `install.ps1` |
| **new-rn-project skill** | Auto-detect stack, create project files, copy hooks, selective rules | `skills/new-rn-project/SKILL.md` |
| **rn-doctor skill** | Run 24 health checks, explain FAILs, offer fixes (interactive in Claude Code) | `skills/rn-doctor/SKILL.md` |
| **doctor CLI script** | Run 24 health checks programmatically (CI/setup scripts) | `scripts/doctor.sh`, `scripts/doctor.ps1` |
| **Git hooks** | Enforce quality gates before commit/push based on profile | `hooks/profiles/{minimal,standard,strict}/{pre-commit,pre-push}.sh` |
| **Pre-tool-use hook** | Block destructive patterns (eas submit, force push, etc.) at runtime | `templates/claude/hooks/pre-tool-use.sh` |
| **settings.json denylist** | Declarative allowlist/blocklist for tool permissions | `templates/claude/settings.json` |
| **Templates** | Project structure, docs, rules, environment setup | `templates/{CLAUDE.md.tmpl, docs/*, rules/*.md, claude/*}` |

## Pattern Overview

**Overall:** Staged scaffolding with stack-aware rule selection

**Key Characteristics:**
- **Stateless installations** - install.sh uses `cp -rn` (no-clobber), doesn't touch existing projects
- **Stack detection** - reads `package.json` to identify 13 dimensions (state, nav, styling, backend, i18n, animation, etc.)
- **Selective rule copying** - only `.claude/rules/*.md` relevant to detected stack are copied to projects
- **Three quality profiles** - minimal (fast D1-D5), standard (balanced), strict (all checks + FTA)
- **Layered blocking** - `settings.json` deny list + `pre-tool-use.sh` patterns block destructive ops
- **Profile persistence** - `~/.rn-harness/.profile` tracks user's chosen level; `/new-rn-project` reads and applies it

## Layers

**Installation Layer (`install.sh`, `install.ps1`):**
- Purpose: Fetch rn-harness repo, deploy templates to `~/.claude/templates/rn-20days/`, install skills and scripts
- Location: Repo root
- Contains: Installer scripts (bash/PowerShell)
- Depends on: Git (clone), SSH access (private repo)
- Used by: Initial setup (D0), updates

**Template Layer (`templates/`):**
- Purpose: Provide skeleton files, docs, rules, and safety configs for projects
- Location: `templates/` in repo; copied to `~/.claude/templates/rn-20days/`
- Contains: CLAUDE.md template with placeholders, 6 doc stubs, 15 knowledge rules, settings.json, hooks/pre-tool-use.sh
- Depends on: Nothing (static files)
- Used by: new-rn-project skill fills placeholders, copies selectively

**Skill Layer (`skills/new-rn-project/`, `skills/rn-doctor/`):**
- Purpose: Orchestrate project init (stack detection, file creation) and health checks
- Location: `~/.claude/skills/` (installed by installer)
- Contains: SKILL.md specifications (no code — implementation happens in Claude Code)
- Depends on: `templates/`, doctor.sh/ps1 for checks
- Used by: Users invoke `/new-rn-project` or `/rn-doctor` in Claude Code

**Script Layer (`scripts/`):**
- Purpose: Provide CLI health checks (doctor.sh/ps1) for automation and non-interactive use
- Location: `~/.rn-harness/scripts/`
- Contains: 24-check doctor script (bash/PowerShell), can output JSON for CI
- Depends on: Bash/PowerShell, Node.js, git, pnpm
- Used by: Pre-commit hooks, CI pipelines, manual health checks

**Hook Profiles (`hooks/profiles/`):**
- Purpose: Define three levels of pre-commit/pre-push quality gates
- Location: `~/.rn-harness/hooks/profiles/{minimal,standard,strict}/`
- Contains: pre-commit.sh, pre-push.sh, and PowerShell equivalents
- Depends on: pnpm scripts (typecheck, lint, format:check, fta, quality:full)
- Used by: Projects copy appropriate profile to `.githooks/` during initialization

**Runtime Safety (`templates/claude/`):**
- Purpose: Block destructive operations via declarative denylist and pattern matching
- Location: `~/.claude/templates/rn-20days/claude/` → copied to project `.claude/`
- Contains: `settings.json` (permission denylist), `hooks/pre-tool-use.sh` (pattern blocker)
- Depends on: Claude Code (respects settings.json), bash (runs pre-tool-use.sh)
- Used by: Claude Code before executing each tool

## Data Flow

### Primary Flow: `/new-rn-project` Initialization

1. **User invokes** `/new-rn-project` in project directory (`src/new-rn-project/SKILL.md:Passo 1`)
2. **Verify location** - confirm CWD is project root, warn if CLAUDE.md exists (`SKILL.md:Passo 1`)
3. **Auto-detect stack** - read `package.json`, map to 13 dimensions (state, nav, styling, backend, i18n, animation, gesture, storage, image-gen, testing, video, monetization, notifications) (`SKILL.md:Passo 1b`)
4. **Show detection table** - display detected values, allow corrections (`SKILL.md:Passo 1b`)
5. **Collect user inputs** - APP_NAME, APP_SLUG, COMPANY, description, languages, monetization, hook profile (`SKILL.md:Passo 2`)
6. **Verify tools** - check node ≥20, pnpm, git, eas-cli (optional) (`SKILL.md:Passo 3`)
7. **Create files without overwriting** (`SKILL.md:Passo 4`):
   - **CLAUDE.md** - from `~/.claude/templates/rn-20days/CLAUDE.md.tmpl`, replace all `{{PLACEHOLDERS}}`
   - **DECISIONS.md** - from `DECISIONS.md.stub`, replace {{APP_NAME}}, {{DATA_INICIO}}
   - **TODO.md** - from `TODO.md.stub`, leave {{FEATURE_*}} for user
   - **docs/{01-06}.md** - copy all 6 phase docs (no substitution)
   - **.claude/settings.json** - copy denylist (only if doesn't exist)
   - **.claude/hooks/pre-tool-use.sh** - copy pattern blocker, make executable
8. **Copy selective rules** (`SKILL.md:Passo 4I`):
   - Always: `patterns.md`, `performance.md`, `security.md`, `accessibility.md`, `forbidden.md`
   - If Zustand: `zustand.md`
   - If Expo Router: `expo-router.md`
   - If Supabase: `supabase.md`
   - If i18next: `i18next.md`
   - If Reanimated: `react-native-reanimated.md`
   - If Gesture Handler: `react-native-gesture-handler.md`
   - If StyleSheet: `styling.md`
   - If expo-video: `expo-video.md`
   - If RevenueCat: `revenue-cat.md`
   - If expo-notifications: `expo-notifications.md`
9. **Configure git hooks** (`SKILL.md:Passo 5`):
   - Read profile from `~/.rn-harness/.profile` (default: strict)
   - Copy hooks from `~/.rn-harness/hooks/profiles/$PROFILE/` to `.githooks/`
   - Run `git config core.hooksPath .githooks`
10. **Generate next-steps checklist** (`SKILL.md:Passo 6`) - install missing deps, run `npx expo install --fix`

**Result:** Project has:
- Filled CLAUDE.md with stack info
- Docs structured for 20-day timeline
- Git hooks enforcing quality gates at commit/push
- .claude/rules/ with only relevant knowledge
- .claude/settings.json + hooks/pre-tool-use.sh blocking destructive ops

### Secondary Flow: `/rn-doctor` Health Checks

1. **User invokes** `/rn-doctor` in project directory (`skills/rn-doctor/SKILL.md`)
2. **Run doctor.sh** (or doctor.ps1 on Windows)
3. **Parse 24 checks** (`scripts/doctor.sh:_out` function):
   - Counts: node version, pnpm, git, eas-cli, package.json, CLAUDE.md, .gitignore, .env commits, .claude/rules/, Expo SDK, RN version, Reanimated, tsconfig strict, babel reanimated plugin, ESLint color-literals, pnpm scripts, secure-store/AsyncStorage, hardcoded keys, .git/, hooks path, app.json bundle/package, eas.json, lineHeight, expo-av
4. **Report results** - format: `[OK/WARN/FAIL] message` + fix suggestion
5. **Exit code** - 0 if no FAILs, 1 if ≥1 FAIL
6. **Skill (interactive)** - explain each FAIL, run suggested fixes after user confirmation
7. **Script (CLI)** - output human-readable or JSON format for CI

**State Management:**
- No persistent state in the framework itself
- Each project maintains its own:
  - CLAUDE.md (project spec)
  - .claude/settings.json (permissions)
  - .claude/rules/ (active knowledge)
  - .githooks/ (active quality gates)
  - .profile in rn-harness install (user's preferred hook level)

## Key Abstractions

**Stack Detection (Dimension Mapping):**
- Purpose: Auto-identify tech choices from `package.json`
- Examples: `zustand.md` copied if "zustand" in deps, `supabase.md` if "@supabase/supabase-js" present
- Pattern: Read package.json, check for package presence, suggest defaults, display table for confirmation
- Implementation: `skills/new-rn-project/SKILL.md:Passo 1b` logic

**Selective Rule Copying:**
- Purpose: Only load relevant knowledge rules to projects
- Examples: A non-Supabase project won't get `supabase.md`; a non-animated project won't get `react-native-reanimated.md`
- Pattern: `if BACKEND == Supabase then cp supabase.md`
- Implementation: Conditional `cp` in new-rn-project step 4I

**Hook Profile Selection:**
- Purpose: Allow users to choose quality gate strictness (D1 fast iteration vs. code freeze)
- Examples: `minimal` = typecheck only; `strict` = typecheck+lint+format+FTA+tests
- Pattern: Read from `~/.rn-harness/.profile`, copy hooks to `.githooks/`, git config core.hooksPath
- Implementation: `install.sh:--profile` flag saves profile; `skills/new-rn-project/SKILL.md:Passo 5` reads and applies

**Destructive Operation Blocking (Two-Layer):**
- **Layer 1 (Declarative):** `settings.json` deny list blocks Bash commands matching patterns at Claude Code level
- **Layer 2 (Runtime):** `pre-tool-use.sh` script intercepts tool calls and blocks regex patterns (e.g., `eas submit`, `supabase db reset`, `git push --force`)
- Pattern: `settings.json` → JSON deny list; `pre-tool-use.sh` → stdin → parse JSON → regex match → exit 2 to block
- Implementation: `templates/claude/settings.json` (deny array), `templates/claude/hooks/pre-tool-use.sh` (bash pattern match)

## Entry Points

**Installation Entry Point (`install.sh`):**
- Location: `install.sh` (repo root)
- Triggers: `curl ... | sh` or `~/.rn-harness/install.sh`
- Responsibilities:
  - Check/update local rn-harness repo via git
  - Save selected profile to `~/.rn-harness/.profile`
  - Copy templates to `~/.claude/templates/rn-20days/`
  - Copy skills to `~/.claude/skills/new-rn-project/` and `rn-doctor/`
  - Make scripts executable

**Skill Entry Point: `/new-rn-project`**
- Location: `skills/new-rn-project/SKILL.md`
- Triggers: User types `/new-rn-project` in Claude Code, must be in project root directory
- Responsibilities:
  - Detect stack from package.json
  - Create/fill CLAUDE.md, docs/, DECISIONS.md, TODO.md
  - Copy git hooks from active profile
  - Copy selective .claude/rules/
  - Copy safety configs (settings.json, pre-tool-use.sh)

**Skill Entry Point: `/rn-doctor`**
- Location: `skills/rn-doctor/SKILL.md`
- Triggers: User types `/rn-doctor` in Claude Code (any directory with package.json)
- Responsibilities:
  - Call doctor.sh with current directory
  - Parse results
  - For each FAIL: explain cause, offer fix, execute after confirmation
  - For WARN: evaluate context, decide if relevant

**CLI Entry Point: `doctor.sh`**
- Location: `~/.rn-harness/scripts/doctor.sh`
- Triggers: `bash ~/.rn-harness/scripts/doctor.sh [--json] [project-dir]`
- Responsibilities:
  - Run 24 checks non-interactively
  - Output human-readable or JSON
  - Exit 0 if no FAILs, 1 if ≥1 FAIL

**Git Hook Entry Points**
- **Pre-commit:** `.githooks/pre-commit` → runs selected profile's checks (minimal: tsc; standard: tsc+lint+format; strict: +FTA)
- **Pre-push:** `.githooks/pre-push` → runs `pnpm quality:full` + Android confirmation prompt

## Architectural Constraints

- **No state persistence in harness** — rn-harness is stateless; per-project state lives in CLAUDE.md, settings.json, .claude/rules/, .githooks/
- **Profile immutability during project** — hooks are copied at init time; changing profile requires manually copying new hooks
- **No-clobber installation** — `install.sh` uses `cp -rn` by default (skip existing), `--force` to override — existing projects never affected
- **Stack detection is one-time** — auto-detection happens only at /new-rn-project time; user must manually edit .claude/rules/ if stack changes later
- **Selective rule application** — rules are copied to project `.claude/rules/`, not dynamically loaded from harness; this allows per-project customization but means harness updates don't auto-propagate
- **Synchronous blocking hooks** — pre-commit/pre-push are synchronous (block until complete or fail), no async/background checks
- **Single profile per install** — `~/.rn-harness/.profile` holds one active profile; projects can override by copying different hooks, but harness tracks only one
- **No circular dependencies** — rules don't import each other; CLAUDE.md doesn't import rules; skills are isolated by file
- **Bash/PowerShell equivalence** — install.ps1 and doctor.ps1 must behave identically to .sh versions; tested separately

## Anti-Patterns

### "I'll add all rules to every project"

**What happens:** new-rn-project copies all 15 rules to .claude/rules/ regardless of stack (defeats selective rule logic)

**Why it's wrong:** Projects load irrelevant rules (e.g., supabase.md in a Firebase project), causing noise and conflicting guidance

**Do this instead:** Follow `skills/new-rn-project/SKILL.md:Passo 4I` — copy only rules matching detected stack. If you later add Supabase to a Firebase project, manually add supabase.md.

### "Hardcode the profile in new-rn-project"

**What happens:** Skill ignores `~/.rn-harness/.profile` and always applies (e.g.) strict hooks

**Why it's wrong:** Users who installed with `install.sh --profile minimal` expect minimal hooks; hardcoding strict violates that choice

**Do this instead:** Read `~/.rn-harness/.profile` (default: strict if missing), use that profile unless user explicitly chooses differently in step 2

### "Run git config in install.sh"

**What happens:** Installer tries to set core.hooksPath globally or in a repo that might not exist yet

**Why it's wrong:** install.sh runs before any project exists; projects might prefer different hook paths; global config affects all repos (bad)

**Do this instead:** Let new-rn-project set core.hooksPath per project after creating .githooks/

### "Update template files in a project after init"

**What happens:** Developer edits ~/.claude/templates/rn-20days/docs/01-spec.md, expects existing projects to see changes

**Why it's wrong:** new-rn-project copies templates to projects at init time; future changes to templates don't propagate (projects own their copies)

**Do this instead:** If templates change, tell users to manually update their projects, or have them re-run /new-rn-project with --force (cautiously)

## Error Handling

**Strategy:** Fail early with actionable guidance

**Patterns:**

- **Permission errors:** If doctor.sh can't read .git/, report WARN instead of error (graceful degradation)
- **Missing files:** doctor.sh checks existence before reading; missing optional files (eas.json, app.json) generate WARN not FAIL
- **Version mismatches:** Extract major.minor from package.json version ranges (`"expo"` → "^56.0.0" → "56"); if major doesn't match, FAIL with upgrade command
- **Install failures:** install.sh checks git access before cloning; if no access, print manual clone instructions and exit 1
- **Hook copy failures:** If cp fails in new-rn-project, warn but continue (don't abort entire wizard)
- **JSON parse errors in pre-tool-use.sh:** If settings.json is malformed, default to allow (safety: don't block on harness bugs)

## Cross-Cutting Concerns

**Logging:** `install.sh`/`install.ps1` use echo/Write-Host to print progress. doctor.sh formats via `_out` function (handles both human and JSON output). Skills print to Claude Code console.

**Validation:** 
- `install.sh` validates `--profile` parameter (must be minimal, standard, or strict)
- `doctor.sh` validates node version parsing (if major < 20, FAIL)
- `new-rn-project` shows stack detection table for user confirmation before proceeding
- Hooks validate command exit codes (exit 1 if check fails)

**Configuration:**
- `~/.rn-harness/.profile` — user's active profile (minimal/standard/strict)
- `~/.claude/templates/rn-20days/` — installed templates (read-only after install)
- `project/.claude/settings.json` — per-project tool permission denylist
- `project/.claude/rules/` — per-project knowledge (subset of templates, selectively copied)
- Environment variables: `RN_HARNESS_DIR`, `CLAUDE_CONFIG_DIR`, `HARNESS_REMOTE`, `HARNESS_CONFIRM`, `HARNESS_ANDROID_OK`
